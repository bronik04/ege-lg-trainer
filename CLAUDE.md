# Правила работы

Тренажёр заданий 15–27 ЕГЭ по китайскому языку: правила, вопросы по правилам, практика
по банку ФИПИ, полный вариант. Статическая страница без сервера; данные собираются до
публикации. Замысел — `docs/superpowers/specs/2026-09-26-ege-lg-trainer-design.md`,
план — `docs/superpowers/plans/2026-09-26-ege-lg-trainer.md`.

## Данные

- `sources/constructor-bank/` не редактировать: это снимок первоисточника. Обновление — только
  `scripts/snapshot_constructor.py` (берёт блоки с тегом «Банк ФИПИ»). Новые задания — файлом
  партии в `sources/generated/`. Партию правят на месте до принятия её разборов (по ревью
  содержания). После публикации задание партии меняют, только чтобы исправить его (ревью,
  сообщение ученика): новое условие или варианты — новый ID, ответы учеников на старое и
  разосланные ссылки с ним пропадут; это пишется в `CHANGELOG.md`.
- `sources/hsk4/` не редактировать: это снимок файла автора с заданиями №26 из материалов HSK 4.
  Обновление — только `scripts/snapshot_hsk.py`, затем `scripts/import_hsk.py`. Blue book не
  берётся (решение автора 04.10.2026). Тексты HSK, как и ФИПИ, не правятся. Задание HSK, во
  фрагментах которого есть ключ задания ФИПИ с соседним иероглифом, сборка не публикует
  (`hintsKeyOf`, раздел в `data/review/duplicates.md`).
- `data/raw/*.json` и `data/questions.json` пишутся только скриптами, руками — никогда.
  Тесты сверяют их с пересборкой.
- Формулировки, варианты и их порядок из источника не правятся. Спорный ключ — не
  исправлять, а отметить `keyConflict` в разборе или записать в `data/review/reading-notes.md`.
  Заменить спорный вариант можно только в копии: задание JSON-партии с тем же условием и полем
  `"replaces": "<ID ФИПИ>"` выходит «Новым заданием», пока автор держит оригинал скрытым и разбор
  оригинала принят (решение закреплено отпечатком). Вернёт автор оригинал с ключом ФИПИ или разбор
  оригинала откроют (`reopen.py` предупредит) — копия станет повтором и уйдёт.
- Разборы, темы и правила задания — в `data/authored/task-NN.json`; добавлять волной
  через `scripts/add_explanations.py`. У каждого неверного варианта — свой разбор
  в контексте предложения; общая фраза и отсылка «повторите правило» не проходят проверку.
- **Статус `accepted` — решение автора**: кнопкой «Проверка» (`Проверка.command` →
  `scripts/review_console.py`) или командой в чате — тогда Claude запускает `accept.py`
  (так принят пилот 26.09.2026: «черновики ок»), с записью в `CHANGELOG.md`. Claude пишет
  только черновики (`draft`). В публикацию попадает только принятое.
- Принятое привязано к тексту: `accept.py` пишет отпечаток `acceptedHash`. Правка принятого
  разбора, правила или вопроса останавливает сборку и `validate.py`. Чтобы поправить принятое —
  `python3 scripts/reopen.py ID…` (черновик уходит с сайта до нового принятия), затем волна и
  принятие автором. Правило уводит с собой свои вопросы и все задания с ним (задание с
  непринятым правилом не публикуется; скрипт называет пустеющие позиции варианта) — ветку с
  такими черновиками сливать в `main` только после принятия. Пометка `keyConflict` и решение
  `keyDecision` входят в отпечаток: снять их — открыть задание, а это решение автора («оставить
  скрытым» кнопка подтверждает, пересчитывая отпечаток).
- «Не так» из кнопки — `data/review/fixes.md`: Claude исправляет пункт волной (он возвращается
  на проверку) и удаляет строку. Пункт из `fixes.md` не принимает ни кнопка, ни `accept.py`.
  «Вернуть с ключом ФИПИ» и «ученик прав» кнопка сама делает черновиком — исправление тоже
  идёт через автора. «Ученик прав» пишет две строки: `issue:N` и строку с ID пункта. Строку
  пункта Claude удаляет, когда перепишет разбор; строку `issue:N` держит, пока исправление не
  опубликовано, затем закрывает сообщение. Решение по спорному ключу — поле `keyDecision` в
  разборе (`hidden` / `restore`), его пишет кнопка; при `restore` задание больше не спорное,
  `keyConflict` при переписывании разбора убирается.
- Примеры в карточках правил не берутся из заданий банка: ученик должен запоминать
  правило, а не ответ. Так же задания не подсказывают друг другу: перед слиянием партии —
  раздел «Подсказки между заданиями и правилами» в `data/review/duplicates.md` (ключ с
  соседним иероглифом в другом задании, карточке или вопросе к правилу).
- Новые задания — по формату ЕГЭ: у №20 и №21 три варианта, у остальных четыре; импорт
  остальное не пропустит.

## Команды

    python3 scripts/import_constructor.py   # sources/constructor-bank → data/raw/fipi.json
    python3 scripts/import_generated.py     # sources/generated → data/raw/generated.json
    python3 scripts/snapshot_hsk.py         # файл автора с заданиями HSK 4 → sources/hsk4/
    python3 scripts/build_bank.py           # data/raw + data/authored → data/questions.json + отчёты
    python3 scripts/validate.py             # инварианты банка, правил и вопросов
    python3 scripts/build_site.py           # dist/index.html — только принятое
    python3 scripts/build_site.py --drafts  # review-build/review.html — с черновиками
    python3 scripts/review_console.py       # кнопка «Проверка» (двойной клик — Проверка.command)
    python3 scripts/accept.py ID… | --task N  # принять по команде автора в чате
    python3 scripts/reopen.py ID…           # вернуть принятое в черновик, чтобы поправить

Тесты: `python3 -m unittest discover -s test -t .` и `node --test test/*.test.mjs`.
Браузерный `test/ui.test.mjs` проходит страницу из `test/fixtures` (и одну сборку из
настоящих данных) в Google Chrome без окна; нужен `npm ci`. Локально без Chrome пропускается,
в CI падает. Фикстуры — `python3 test/fixtures/make_fixture.py`.
В Python 3.14 стандартный пакет `test` перехватывает импорт, поэтому в `test/` лежит
`__init__.py`, а discover запускается с `-t .`. Паттерн `test/*.test.mjs` пишется без
кавычек: его раскрывает shell (так работает в любой версии Node, в том числе без встроенного глоба).

## Интерфейс

- Весь текст из банка выводится через `textContent`; разметку из данных не исполнять.
- Облик «тетрадь» — `docs/superpowers/specs/2026-09-26-notebook-redesign-design.md`: цвета
  только токенами из `src/app.css` (обе темы), чёрного фона и кнопок нет, основная кнопка —
  синяя ручка `--pen`. Из сети — только стили шрифтов (Google Fonts, jsDelivr), скриптов нет.
- Работа без сети — только у опубликованной страницы: `build_site.py` кладёт рядом с
  `index.html` манифест, иконки из `src/pwa/` и `sw.js` с версией — отпечатком страницы.
  Страница берётся сначала из сети, без сети — из кэша; шрифты — из своего кэша. Добавили файл
  рядом со страницей — впишите его в `PWA_FILES` (`build_site.py`) и `CORE` (`src/pwa/sw.js`).
  Путь `sw.js` не переименовывать. Сломалась работа без сети у учеников — аварийное выключение:
  Actions → Deploy to GitHub Pages → Run workflow со снятой галочкой «offline» (одна выкладка,
  без тестов). Выйдет сборка `build_site.py --no-offline` (под именем `sw.js` — `sw-off.js`, он
  удалит кэши и снимет себя). Чтобы выключатель пережил следующие push — переменная репозитория
  `OFFLINE = false` (Settings → Secrets and variables → Actions → Variables); починили — удалить.
- Превью ссылки в мессенджерах — теги Open Graph у опубликованной страницы (`share_head` в
  `build_site.py`, адрес сайта — `SITE_URL` в `scripts/common.py`) и картинка
  `src/og/og-image.jpg` рядом с `index.html`. Странице она не нужна, поэтому в `PWA_FILES`
  и `CORE` не входит. Правите `src/og/og-image.html` — перерисуйте
  `node scripts/render_og_image.mjs` (Chrome и сеть) и закоммитьте jpg. Чисел на картинке нет.
- Чистая логика — `src/logic.mjs` (тестируется в Node), DOM — `src/app.js`.
  При сборке `export` вырезается, и оба файла попадают в один скрипт страницы.
- Ссылки учителя — маршрут с параметрами: `#/practice?topics=…&tasks=…&origins=…&size=…`
  (подборка), `#/practice?ids=…` (те же задания), `#/variant?ids=…` (тот же вариант).
  Страница сразу заменяет адрес обычным, незнакомые ID и темы отбрасывает и говорит об этом.
  Та же ссылка повторно (ученик вернулся из чата) — начатое продолжается, решённое показывает
  итог. Меняете маршруты — не ломайте уже разосланные ссылки.
- Подборка практики берёт номера поровну (`pickRound`: номера по кругу, внутри номера — случайно;
  раунд «все» — всё вперемешку). Полный вариант — только задания формата ЕГЭ: `buildVariant` и
  замена снятого задания в `pruneProgress` не берут задания HSK (`origin: "hsk"`).
- Часы полного варианта: 40 минут на раздел 3 по спецификации ЕГЭ 2026 (`VARIANT_MINUTES`).
  Идут, только пока открыт незавершённый вариант и страница видна; по истечении вариант не
  обрывается. Сохранения без действия ученика (табло, скрытие, закрытие) дописывают в
  хранилище только `elapsedMs` того же варианта, а запись другой вкладки страница подхватывает
  (событие `storage`) — вкладки не затирают ответы друг друга.
- Отчёт учителю — текст для мессенджера и последней строкой код `EGELG1:<base64 JSON без «=»>`
  (`encodeReport` / `decodeReports` в `logic.mjs`; не base64url — «_» и «-» мессенджеры
  превращают в разметку). В коде — ответы по ID и счёт, который видел ученик; чужой код
  проверяется по типам и пределам. Заданий в коде — не больше `REPORT_MAX_TASKS` (100):
  раунд больше отчёта не предлагает. Страница `#/teacher` сводит вставленные
  отчёты, ничего не отправляя и не сохраняя. Меняете поля кода — новый префикс, а страница
  учителя читает и старые. Имя ученика хранится только в его браузере
  (`ege-lg-trainer:student`).
- Ссылка «Сообщить об ошибке» ведёт в issues (`ISSUES_URL` в `scripts/common.py`) и несёт
  ID задания, условие, выбранный ответ и ключ — ничего о самом ученике.
- Прогресс — `localStorage`, ключ `ege-lg-trainer:progress`, версия структуры в
  `PROGRESS_VERSION` (сейчас 2: у ответа есть `review` — интервальное повторение).
  Меняете структуру — поднимите версию, добавьте старую в `READABLE_VERSIONS` и не роняйте
  старые данные. Страница не перезаписывает прогресс более новой версии (и записанный другой
  вкладкой после загрузки — сброс и файл в этом режиме закрыты), а старый перед
  переносом копирует в `ege-lg-trainer:progress:vN`. Выкладку с новой версией прогресса не
  откатывают ниже неё — ошибки исправляют следующим коммитом.
  Необязательное поле, которое старый код сохраняет как есть, версии не требует: так в сессии
  варианта хранится `elapsedMs` (сессия копируется целиком). Снятое с публикации задание
  уходит из сессий (`pruneProgress`): в начатом варианте его место занимает задание того же номера.
  Файл прогресса («Сохранить в файл» в банке) — тот же объект с полем `app`; при загрузке
  он объединяется с текущим (`mergeProgress`), а не заменяет его. Старые файлы после смены
  версии тоже должны читаться.

Каждое заметное изменение — короткая запись в `CHANGELOG.md` рядом с коммитом.

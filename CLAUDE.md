# Правила работы

Тренажёр заданий 15–27 ЕГЭ по китайскому языку: правила, вопросы по правилам, практика
по банку ФИПИ, полный вариант. Статическая страница без сервера; данные собираются до
публикации. Замысел — `docs/superpowers/specs/2026-09-26-ege-lg-trainer-design.md`,
план — `docs/superpowers/plans/2026-09-26-ege-lg-trainer.md`.

## Данные

С 24.10.2026 задания приходят только из **единого банка заданий ЕГЭ** (`~/Documents/Projects/ege-task-bank`,
данные на Яндекс.Диске); решения автора — в описании банка (`02-ЕГЭ/01-Банк_заданий/Единый_банк_описание.md`).

- `sources/bank/` не редактировать: это снимок выгрузки банка (`export-sites lg`) с контрольной суммой.
  Обновление — только `scripts/snapshot_bank.py <выгрузка>`; сайт собирается в GitHub Actions из этого снимка.
- **Задания правятся в банке, а не здесь.** Новые задания — порцией в банк (черновики → ревью → «проверено»),
  затем новая выгрузка и снимок. Здесь задание не создаётся и не исправляется.
- **ID задания не меняется** (решение автора): он задаётся один раз и хранится в банке (`lgIds`, команда
  `link lg`). Новое задание из банка получает `<q|h|g><номер>-<8 знаков ID блока>`, а `import_bank.py`
  складывает такие пары в `data/review/new-links.json` — их сразу записывают в банк
  (`npm --prefix ~/Documents/Projects/ege-task-bank run -s bank -- link lg --file <абсолютный путь> --why …`).
- **Явные ошибки ФИПИ и HSK правятся в банке** (решение автора): правка доходит и до тренажёра, и до
  конструктора. Старые копии с `replaces` (поле теперь в разборе) работают как раньше; новых не заводить.
  Задание HSK, подсказывающее ключ ФИПИ, по-прежнему не публикуется (`hintsKeyOf`).
- Задание поправили в банке — ID и публикация прежние, принятый разбор попадает в
  `data/review/recheck.md` («перепроверить»); после вердикта ревьюера — `accept.py ID` (только по ID,
  `--task` перепроверку не принимает). Если разбор структурно больше не подходит (сменился ключ),
  задание уходит с сайта (раздел «Сняты с сайта до нового разбора»): `reopen.py` → новая волна → ревью
  → `accept.py`; неподходящий разбор `accept.py` не примет.
- Банк снял задание с сайта (черновик или «только для уроков») или задание ждёт решения (черновик,
  связанный через `--allow-draft`) — его нет в выгрузке, тренажёр его не публикует, разбор остаётся
  (`recheck.md`, раздел «Не идут на сайт»). Решат в банке — задание вернётся с прежним ID.
- Пометку `replaces` в разборе волна (`add_explanations.py`) сохраняет; в отпечаток принятия она не
  входит — это решение о публикации, его ставит Claude по решению автора.
- `data/raw/bank.json` и `data/questions.json` пишутся только скриптами, руками — никогда.
  Тесты сверяют их с пересборкой.
- Разборы, темы и правила задания — в `data/authored/task-NN.json`; добавлять волной
  через `scripts/add_explanations.py`. У каждого неверного варианта — свой разбор
  в контексте предложения; общая фраза и отсылка «повторите правило» не проходят проверку.
- **Статус `accepted` ставится по итогам ревью** (решение автора 24.10.2026): агент-ревьюер — не тот,
  кто писал, — проверяет задание вместе с разбором; после его вердикта Claude запускает `accept.py` с записью
  в `CHANGELOG.md`. Агентов — только с согласия автора на каждый запуск, не больше трёх одновременно.
  Об ошибках автор сообщает потом — их исправляют волной и снова ревью. Claude пишет только черновики
  (`draft`); в публикацию попадает только принятое. Кнопка «Проверка» (`Проверка.command`) остаётся для
  сообщений учеников и для автора, если он хочет принять сам.
- Принятое привязано к тексту: `accept.py` пишет отпечаток `acceptedHash`. Правка принятого
  разбора, правила или вопроса останавливает сборку и `validate.py`. Чтобы поправить принятое —
  `python3 scripts/reopen.py ID…` (черновик уходит с сайта до нового принятия), затем волна и
  принятие автором. Правило уводит с собой свои вопросы и все задания с ним (задание с
  непринятым правилом не публикуется; скрипт называет пустеющие позиции варианта) — ветку с
  такими черновиками сливать в `main` только после принятия. Пометка `keyConflict` и решение
  `keyDecision` входят в отпечаток: снять их — открыть задание, а это решение автора («оставить
  скрытым» кнопка подтверждает, пересчитывая отпечаток).
- «Не так» из кнопки — `data/review/fixes.md`: Claude исправляет пункт волной (он возвращается
  на проверку) и удаляет строку. Пункт из `fixes.md` не принимает ни кнопка, ни `accept.py`.
  «Вернуть с ключом ФИПИ» (у заданий HSK — «с ключом HSK») и «ученик прав» кнопка сама делает черновиком — исправление тоже
  идёт через автора. «Ученик прав» пишет две строки: `issue:N` и строку с ID пункта. Строку
  пункта Claude удаляет, когда перепишет разбор; строку `issue:N` держит, пока исправление не
  опубликовано, затем закрывает сообщение. Решение по спорному ключу — поле `keyDecision` в
  разборе (`hidden` / `restore`), его пишет кнопка; при `restore` задание больше не спорное,
  `keyConflict` при переписывании разбора убирается.
- Примеры в карточках правил не берутся из заданий банка: ученик должен запоминать
  правило, а не ответ. Так же задания не подсказывают друг другу: перед слиянием новых заданий —
  раздел «Подсказки между заданиями и правилами» в `data/review/duplicates.md` (ключ с
  соседним иероглифом в другом задании, карточке или вопросе к правилу).
- **Слова для тренировки тонов (№15)** — не задания банка, а отдельный слой: слова HSK 2.0 уровней 1–4
  из 2–3 иероглифов. Замысел — `docs/superpowers/specs/2026-10-26-tone-words-design.md`.
  `sources/words/hsk2-words.json` (выписка `extract_words.py` из таблиц автора и Anki) и `data/tone-words.json`
  (результат `build_tones.py`) руками не правятся; решения по слову — `data/words/overrides.json`
  (чтение, перевод или `skip` с причиной), спорные слова — в `data/review/tones-report.md`. Слово берётся,
  только если источники сходятся в тонах (лёгкий тон, 一/不, опечатки расходятся — решает автор) и слова нет среди
  заданий №15 банка. Варианты и разбор собираются по слову сами (`scripts/tones.py`), общих фраз нет.
  Принятие — как у заданий: два независимых ревьюера → `accept_tones.py` (отпечаток слова; правка
  возвращает его в черновик). На сайт идут только принятые слова.
- Новые задания — по формату ЕГЭ: у №20 и №21 три варианта, у остальных четыре, у №26 — четыре
  разные последовательности A, B, C; задание не по формату импорт оставит черновиком с замечанием
  в `data/review/import-report.md`, на сайт оно не выйдет, пока его не поправят в банке.

## Команды

    python3 scripts/snapshot_bank.py <файл>  # выгрузка банка (export-sites lg) → sources/bank/
    python3 scripts/import_bank.py          # sources/bank → data/raw/bank.json (+ new-links.json)
    python3 scripts/build_bank.py           # data/raw + data/authored → data/questions.json + отчёты
    python3 scripts/validate.py             # инварианты банка, правил и вопросов
    python3 scripts/build_site.py           # dist/index.html — только принятое
    python3 scripts/build_site.py --drafts  # review-build/review.html — с черновиками
    python3 scripts/review_console.py       # кнопка «Проверка» (двойной клик — Проверка.command)
    python3 scripts/accept.py ID… | --task N  # принять после ревью (и перепроверенное из recheck.md)
    python3 scripts/reopen.py ID…           # вернуть принятое в черновик, чтобы поправить
    python3 scripts/extract_words.py        # таблицы HSK1–4 + Anki → sources/words/ (редко, по Диску)
    python3 scripts/build_tones.py          # слова тренировки тонов → data/tone-words.json + отчёт
    python3 scripts/accept_tones.py …       # принять слова после ревью (--list, --level N, --all)

Тесты: `python3 -m unittest discover -s test -t .` и `node --test test/*.test.mjs`.
Браузерный `test/ui.test.mjs` проходит страницу из `test/fixtures` (и одну сборку из
настоящих данных) в Google Chrome без окна; нужен `npm ci`. Локально без Chrome пропускается,
в CI падает. Фикстуры — `python3 test/fixtures/make_fixture.py`.
В Python 3.14 стандартный пакет `test` перехватывает импорт, поэтому в `test/` лежит
`__init__.py`, а discover запускается с `-t .`. Паттерн `test/*.test.mjs` пишется без
кавычек: его раскрывает shell (так работает в любой версии Node, в том числе без встроенного глоба).

## Интерфейс

- Весь текст из банка выводится через `textContent`; разметку из данных не исполнять.
- Облик — дизайн-система «Тушь и киноварь» (как у тренажёра по лингвострановедению), замысел —
  `docs/superpowers/specs/2026-10-27-ink-cinnabar-design.md`. Токены — `src/ink/ink-tokens.css` (копия системы,
  не править: правка идёт в систему, сюда — новая копия); цвета в `src/app.css` только семантикой системы или
  псевдонимами в его начале, чёрного фона и кнопок нет, основная кнопка — киноварная печать `--fill-accent`.
  Из сети — только стили шрифтов (Google Fonts, jsDelivr), скриптов нет.
- Пропуск в условии (и в предложении формулировки вопроса по правилу) до ответа — всегда одна клетка 田字格, какой бы длины ни были варианты:
  ширина не должна подсказывать ответ (решение автора 10.10.2026). Вписанный ответ раздвигает
  пропуск по числу знаков.
- После ответа предложение с правкой остаётся на экране (`afterAnswer`): страница сдвигается
  самое большее до предложения у верхнего края. Фокус — на «Дальше», только если её видно,
  иначе на разборе: пробел листает разбор, Enter ведёт дальше. Начало разбора за нижним краем
  (низкий экран) — фокус на условии задания. Новый экран — с начала страницы (`holdTop`).
- Работа без сети — только у опубликованной страницы: `build_site.py` кладёт рядом с
  `index.html` манифест, иконки из `src/pwa/` и `sw.js` с версией — отпечатком страницы.
  Страница берётся сначала из сети, без сети — из кэша; шрифты — из своего кэша. Добавили файл
  рядом со страницей — впишите его в `PWA_FILES` (`build_site.py`) и `CORE` (`src/pwa/sw.js`).
  Путь `sw.js` не переименовывать. Сломалась работа без сети у учеников — аварийное выключение:
  Actions → Deploy to GitHub Pages → Run workflow со снятой галочкой «offline» (одна выкладка,
  без тестов). Выйдет сборка `build_site.py --no-offline` (под именем `sw.js` — `sw-off.js`, он
  удалит кэши и снимет себя). Чтобы выключатель пережил следующие push — переменная репозитория
  `OFFLINE = false` (Settings → Secrets and variables → Actions → Variables); починили — удалить.
- Превью ссылки в мессенджерах — теги Open Graph у опубликованной страницы (`share_head` в
  `build_site.py`, адрес сайта — `SITE_URL` в `scripts/common.py`) и картинка
  `src/og/og-image.jpg` рядом с `index.html`. Странице она не нужна, поэтому в `PWA_FILES`
  и `CORE` не входит. Правите `src/og/og-image.html` — перерисуйте
  `node scripts/render_og_image.mjs` (Chrome и сеть) и закоммитьте jpg. Чисел на картинке нет.
- Вкладка «Тоны» (`#/tones`) — круг по словам HSK 2.0 к №15: уровень, длина слова, состояние, размер как в
  практике. Круг идёт в той же сессии `progress.round` с пометкой `mode: "tones"` (версия прогресса не
  меняется), ответы пишутся в `progress.questions` под ID `w15-…`, карточку, разбор и итог показывает общий
  код раунда. «Практика» круг тонов (начатый на вкладке «Тоны») не открывает; ссылки и отчёта учителю у него нет (ID слов учитель не
  разберёт). Нет принятых слов — нет и вкладки.
- Слова тренировки тонов — ещё и задания №15 «Практики» (источник «Слова HSK 1–4», `origin: "words"`): они
  входят в счёт №15 и в «Банк». В круге практики слова — отдельная группа (`pickRound`), чтобы сотни слов не
  вытесняли задания ФИПИ; в полный вариант и в замену снятого задания не входят (как `hsk`).
- Дальше после ответа ведут Enter и пробел (`data-enter`, `data-space` на «Дальше»; в варианте пробел — только у позиции с ответом, удержанная клавиша экраны не листает); «Начать раунд» — только Enter.
- «Практика» и «Тоны» начинаются с «Следующего раунда» (`nextRound`), как главная тренажёра по лингвострановедению:
  строка о выбранном (номера, правила, источник, состояние), сколько заданий войдёт и «Начать раунд»; настройки — ниже.
  На телефоне, пока эта кнопка за краем экрана, её повторяет панель у нижнего края (`startBar` / `syncStartBar`).
- Чистая логика — `src/logic.mjs` (тестируется в Node), DOM — `src/app.js`.
  При сборке `export` вырезается, и оба файла попадают в один скрипт страницы.
- Ссылки учителя — маршрут с параметрами: `#/practice?topics=…&tasks=…&rules=…&origins=…&size=…`
  (подборка), `#/practice?ids=…` (те же задания), `#/variant?ids=…` (тот же вариант).
  Страница сразу заменяет адрес обычным, незнакомые ID, темы и правила отбрасывает и говорит об этом.
  Правило (`rules`, «Грамматика» под оглавлением) уточняет только свой номер, другие отмеченные
  номера берутся целиком; снят номер — уходят и его правила (`fitRules`), ссылка только с
  правилами отмечает их номера (`ruleTasks`).
  Та же ссылка повторно (ученик вернулся из чата) — начатое продолжается, решённое показывает
  итог. Меняете маршруты — не ломайте уже разосланные ссылки.
- Подборка практики берёт номера поровну (`pickRound`: номера по кругу, внутри номера — случайно;
  раунд «все» — всё вперемешку). Полный вариант — только задания формата ЕГЭ: `buildVariant` и
  замена снятого задания в `pruneProgress` не берут задания HSK (`origin: "hsk"`).
- Часы полного варианта: 40 минут на раздел 3 по спецификации ЕГЭ 2026 (`VARIANT_MINUTES`).
  Идут, только пока открыт незавершённый вариант и страница видна; по истечении вариант не
  обрывается. Сохранения без действия ученика (табло, скрытие, закрытие) дописывают в
  хранилище только `elapsedMs` того же варианта, а запись другой вкладки страница подхватывает
  (событие `storage`) — вкладки не затирают ответы друг друга.
- Отчёт учителю — текст для мессенджера и последней строкой код `EGELG1:<base64 JSON без «=»>`
  (`encodeReport` / `decodeReports` в `logic.mjs`; не base64url — «_» и «-» мессенджеры
  превращают в разметку). В коде — ответы по ID и счёт, который видел ученик; чужой код
  проверяется по типам и пределам. Заданий в коде — не больше `REPORT_MAX_TASKS` (100):
  раунд больше отчёта не предлагает. Страница `#/teacher` сводит вставленные
  отчёты, ничего не отправляя и не сохраняя. Меняете поля кода — новый префикс, а страница
  учителя читает и старые. Имя ученика хранится только в его браузере
  (`ege-lg-trainer:student`).
- Ссылка «Сообщить об ошибке» ведёт в issues (`ISSUES_URL` в `scripts/common.py`) и несёт
  ID задания, условие, выбранный ответ и ключ — ничего о самом ученике.
- Прогресс — `localStorage`, ключ `ege-lg-trainer:progress`, версия структуры в
  `PROGRESS_VERSION` (сейчас 2: у ответа есть `review` — интервальное повторение).
  Меняете структуру — поднимите версию, добавьте старую в `READABLE_VERSIONS` и не роняйте
  старые данные. Страница не перезаписывает прогресс более новой версии (и записанный другой
  вкладкой после загрузки — сброс и файл в этом режиме закрыты), а старый перед
  переносом копирует в `ege-lg-trainer:progress:vN`. Выкладку с новой версией прогресса не
  откатывают ниже неё — ошибки исправляют следующим коммитом.
  Необязательное поле, которое старый код сохраняет как есть, версии не требует: так в сессии
  варианта хранится `elapsedMs` (сессия копируется целиком). Снятое с публикации задание
  уходит из сессий (`pruneProgress`): в начатом варианте его место занимает задание того же номера.
  Файл прогресса («Сохранить в файл» в банке) — тот же объект с полем `app`; при загрузке
  он объединяется с текущим (`mergeProgress`), а не заменяет его. Старые файлы после смены
  версии тоже должны читаться.

Каждое заметное изменение — короткая запись в `CHANGELOG.md` рядом с коммитом.
